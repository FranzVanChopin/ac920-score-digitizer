# 大模型协作概述（抽象版）

本项目采用“人工确定目标与验收、多模型辅助开发、多工作线并行验证、版本冻结后集成”的协作方式。模型主要承担资料核对、代码实现、实验脚本、性能分析和可视化制作；关键接口选择、实物制作、测试反馈和最终取舍由团队完成。

协作覆盖 Claude 的识别算法与加速工作，以及多个 Codex Project/并行会话中的板级采集、符号关系优化、独立作品复现、输入质量实验、系统联调和宣传制作。并行任务通过图像接口约定、结构化结果、发布清单和验证报告交接，而不是互相覆盖工作目录或依靠模型之间共享隐式记忆。

主链路为：摄像头采集与图像处理 → 固定纸面比例输出与完成标记 → 单卡文件交接 → 方向转正及识别预处理 → 共享网络与几何/关系分析 → 节奏解码和多页合并 → MusicXML → 乐谱显示与音频播放。当前神经网络推理由 PS/A53 执行，FPGA 负责采集和像素流处理；未部署的 PL 推理方案只作为实验资料。

Claude 侧沉淀了共享网络、C++ 几何与解码加速、常驻进程和多页流水线，并形成可校验的 v16 识别发布包；Codex 多条工作线分别完成了采集与控制、接口集成、Linux 界面与曲库、回归诊断、实验比较和技术展示。算法优化线中没有通过准确率或耗时保护门的候选保持隔离；宣传线中的 AI 视频尝试、最终实拍录屏和原理动画分别标注，未将生成画面当作实机性能证据。

协作的主要经验是把“提出方案”和“完成验证”分开：先写明输入输出与责任边界，再做隔离修改，比较实际产物和时间开销，通过后才集成；遇到错误则根据日志缩小范围、保留旧版并记录修正依据。能生成文件、能显示画面和识别内容正确属于不同验收层级。

本说明是事后整理的工程方法总结，不是逐字对话、模型内部推理或个人操作记录。文件中不保留原始聊天、会话编号和个人目录。
