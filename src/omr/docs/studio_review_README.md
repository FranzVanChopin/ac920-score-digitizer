# Score Studio（Codex 10-30）检查结果

对象：Codex 的 `AC920_IMX477_ScoreStudio_UI1_Light1_20261030`（512 GB 单卡系统，Linux 识别界面 + 乐谱库播放）。

数据：开发板上的识别结果 `/var/lib/ac920-onecard/results`，已拷到 `board_studio/`；实拍照片 Grey/00-00、01-00。

## 1. 主要问题：照片被倒着识别（不是播放器的问题）

- 单卡支架上的相机比 10-29 镜头对比的支架转了 180°。配置 `/etc/ac920-onecard.json` 里还是 `rotate: ccw`，转正后整页上下颠倒：小节号、"presto ♩=176" 都是倒的，谱号在右端。
- 识别仍然找到了 14 行谱、21 个小节，因为小节线上下对称。但音高是镜像的，节奏是从右往左读的。
- 板上 3 页的 headers：每行谱都没找到谱号，调号都是 0，没有一个音带升降号。

| 同一张实拍（01-00），桌面重跑 | 与 PDMX 转谱比，完全正确的音符 | 谱号 / 调号 |
|---|---|---|
| `ccw`（板上现在的设置） | **3 / 511（0.6%）** | 都没找到 / 0 |
| `cw` | **340 / 511（66.5%）** | 高音 + 低音 / 4 个升号（正确） |

所以现在乐谱库里的乐谱和声音基本是乱的，"播放不好"的主要原因在这里。

**立即修复**（需要 root，由用户输入 sudo）：

```
sudo sed -i 's/"rotate": *"ccw"/"rotate": "cw"/' /etc/ac920-onecard.json
sudo mv /var/lib/ac920-onecard/results /var/lib/ac920-onecard/results.upside-down-20261030
sudo systemctl restart ac920-panel
```

然后在界面里重新识别各首。Codex 引擎里的旧版 album 只按 Grey 的 sha256 判断是否识别过，所以必须把旧结果挪开，否则会直接沿用倒着识别的结果。

**根本修复（识别端，已完成，`album/omr_album.py`）：**
- `--rotate auto`（新的默认值）：一页的大多数行谱都没找到谱号（上下颠倒时谱号在右端，没人去那里找），就把这页转 180° 重新识别，保留谱号找到得多的那次，之后的页沿用这个方向。
- 每页记录所用的方向和谱号找到的比例。改了 `--rotate` 后，旧方向的结果会自动重做。
- 桌面测试：混合两种支架的相册（两张单卡实拍 + 一张镜头对比照片）全部自动转对，谱号都是 100% 找到；再运行一次全部跳过。代价是方向变化时多识别一页，开发板上约 35 s。
- Codex 的 `patch_progress.py` 用到的锚点 `if r.get("ready"):` 仍然只出现一次，所以 Codex 可以把新版装进引擎，再把配置改成 `rotate: auto`。

## 2. 实拍质量（与播放无关，但影响识别）

| 照片 | 中心边缘宽度（谱线 / 符干、小节线） | 识别结果 |
|---|---|---|
| 00-00 | 4.5 / **6.0 px**，右上角符干 7.8 px | 17 小节（应为 21） |
| 01-00 | 4.1 / **7.9 px** | 21 小节，66.5% |
| 10-29 镜头对比，8 mm F2.8 | 3.5 / 3.1 px | 21 小节，67–70% |

- 只有竖线（符干、小节线）明显发虚，谱线还好。这种单方向的模糊多半是曝光时相机在动：曝光 94.6 ms，按 S1 时可能把支架按晃了。
- 建议采集端按键后延时约 0.5–1 s 再取帧（像相机的自拍延时）；或者加强照明，把曝光缩短到 30 ms 以内。

## 3. 播放器本身（Codex 的 `render_score.py` 和 `panel_ui.py`）

用板上的两首结果，在桌面上按原代码（复制件）渲染后测量：

| 项目 | 现状 | 问题 | 建议 |
|---|---|---|---|
| 音色 | 自制合成：正弦波加 2–4 次谐波，谐波很快衰减，起音 6 ms，按指数衰减，松键后 0.15 s 截断 | 听起来像电子蜂鸣或风琴，不像钢琴：没有击弦的瞬态、没有琴弦的非谐性、没有混响。（没有削波，峰值 0.53–0.59） | 用 **FluidSynth + 钢琴 SoundFont**（Ubuntu 22.04 arm64 有 `fluidsynth` 2.2.5，可离线安装）：`fluidsynth -ni -r 48000 -F score.wav piano.sf2 score.mid`，用 C 合成，比现在的 Python 循环快，自带混响 |
| 力度 | MIDI 里所有音符的力度都是 90 | 完全没有强弱，很机械 | 简单处理就有效：上方旋律略强，伴奏略弱，强拍 +5 |
| 速度 | MusicXML 里没有速度记号，Verovio 默认 ♩=120 | 《月光》第三乐章标注 ♩=176，播放慢了约 30% | 界面上加速度调节（例如乐谱库里 S1 短按切换 0.75× / 1× / 1.25× / 1.5×）；识别端暂时读不出速度记号的文字 |
| 延音 | 没有踏板，音符按时值截断 | 琶音很干 | SoundFont 的自然衰减已经能改善；可选按小节自动加踏板 |
| 显示：符杠 | 识别结果里没有 `<beam>`，八分、十六分音符各自带符尾 | 和 MuseScore 的样子差很多，难读 | 在显示副本里按拍自动加符杠（每拍一组，同一声部）。这是常规做法，Codex 的 `notation_view.prepare` 已经在补 type、dot，可以一起补 |
| 显示：调号和谱号 | 识别结果没有写 `<key>` 和 `<clef>`；Codex 只是默认补了高音、低音谱号 | 升降号调的曲子每个音都会标临时记号；左手用高音谱号的段落会显示错 | **识别端补：** `headers.json` 里已经有每行的谱号和调号（转对方向后 4 个升号是对的），由我写进 page.musicxml |
| 显示：大小 | Verovio 页面 1880×1100，scale 50，显示在 858×420 的卡片里，每页只有约 4 个小节 | 谱面偏小，约每 8 s 翻一页 | 播放时全屏显示，每页放更多小节；用 timemap 高亮当前小节 |

## 4. 建议顺序

1. **立即：** 用第 1 节的三条命令把方向改成 `cw`，重新识别。这一步之后播放的才是正确的音乐。
2. **识别端（我）：** 10-30 已完成。album 输出的曲目文件 `SS.musicxml` 现在带有谱号、调号、临时记号、音符类型和按拍分组的符杠（`album/engrave.py`），发声的音符不变。方向按用户的决定固定为 `ccw`，放反时会给出提示。
3. **Codex：** FluidSynth 钢琴音色、力度、速度调节、自动符杠、全屏和当前小节高亮。
4. **Codex：** 拍照防抖（按键延时取帧，或缩短曝光）。
