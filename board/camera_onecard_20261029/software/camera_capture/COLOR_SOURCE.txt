White balance at 6500 K
----------------------
Use the enabled rpi.awb algorithm's ct_curve, not the disabled rpi.nn.awb
curve in the same JSON. The two enclosing samples are:

  CT K    ctR       ctB
  6125    0.3129    0.7100
  6671    0.3065    0.7200

Linear interpolation with t=(6500-6125)/(6671-6125)=375/546 gives:
  ctR = 0.30850439560439563
  ctB = 0.7168681318681318

Awb::setColourTemperature in awb.cpp:232-246 applies reciprocal ratios:
  R gain = 1/ctR = 3.2414449007797277
  G gain = 1
  B gain = 1/ctB = 1.3949566950256764

Round 256 times each gain to nearest integer for the sensor interface:
  R/G/B Q8 = 830 / 256 / 357 = 0x033e / 0x0100 / 0x0165
  Applied R/G/B = 3.2421875 / 1 / 1.39453125.

Do not multiply these fixed-temperature gains by sensitivity_r/b=1.05.
Those factors participate in the Bayesian automatic algorithm's statistic
normalization and fitted result; the upstream manual-temperature path above
does not multiply them into its result. The current application does not run
that Bayesian AWB algorithm.

Raspberry Pi normally applies these balance gains in its ISP. Here the
application uses the same provisional gain ratios in the IMX477's individual
digital-gain controls. Register evidence, deliberately restricted range and
readback/failure handling are documented in IMX477_COLOR_REGISTERS.txt.
Moving gain to the sensor changes where clipping and quantization occur;
these values alone do not guarantee identical Raspberry Pi image output.

Colour correction matrix at 6500 K
----------------------------------
The rpi.ccm entries at 5881 K and 7600 K are:

  M5881 = [ 2.18464  -0.95493  -0.22971
           -0.36826   2.00298  -0.63471
           -0.15219  -0.38055   1.53274 ]

  M7600 = [ 2.30687  -0.97295  -0.33392
           -0.30872   2.32779  -1.01908
           -0.17761  -0.55891   1.73651 ]

calculateCcm in ccm.cpp:114-128 linearly interpolates each coefficient.
For t=(6500-5881)/(7600-5881)=619/1719, use M=(1-t)*M5881+t*M7600:

  M6500 = [ 2.228654176847004    -0.9614188772542175  -0.2672352995927865
           -0.3468200581733566    2.119941832460733   -0.7731189761489238
           -0.16134356602675973  -0.4447762012798139   1.6061161663758 ]

The array is RGB row-major, with column-vector multiplication:
  output_linear_RGB = M6500 * input_white_balanced_linear_RGB.
The first row computes output red from input R/G/B; do not transpose it.
The row-major matrix storage is explicit in ccm.cpp:180-183, and vc4.cpp:
387-394 forwards it to the ISP in the same order. RGB2Y and matrix composition
in ccm.cpp:131-146 corroborate the forward multiplication convention.
No additional saturation transform is included in this application's matrix.

Implementation boundaries
--------------------------
The sensor applies white balance once. capture_color.c applies only this
matrix after approximately decoding the existing PL gamma LUT, then clamps
and gamma-encodes the result. Its BGR memory layout is converted to RGB for
the calculation. Signed intermediate values are retained through the matrix;
do not clamp each product or negative coefficient separately.

The decoder models the PL's black removal, gamma-2.2 and 10-to-8-bit
quantization. Do not remove the black pedestal a second time. Inverting an
8-bit quantizer cannot recover lost precision, clipped sensor highlights or
an incorrect physical black-level assumption. A future linear high-bit-depth
ISP path would avoid this approximation.

The fixed 6500 K profile is not a guarantee for an emissive display merely
labelled 6500 K: display spectra, IR filter, lens and illumination all matter.
Use an unclipped white/grey target under the actual light to set sensor gains
once, then retain them while testing saturated colours. The 'w' command uses
only the explicitly selected neutral central ROI; it must not be used on a
solid-colour target. An accepted white measurement does not calibrate the
full matrix. The application retains this fixed matrix after white balance
calibration; that is a deliberate initial implementation limit.

Do not infer an accurate profile from the earlier overexposed test photos.
Near-clipping statistics and register readback support diagnosis but do not
prove colour accuracy. Capture real unclipped neutral/colour targets on this
unit before claiming the correction is physically verified.
