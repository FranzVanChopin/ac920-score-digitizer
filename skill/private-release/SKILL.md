# 隐私友好的技术交接

## 工作方法

先确定交付对象和所需证据。通过允许列表选入技术报告、必要运行日志、构建说明和可复用模板；从空目录组装新的发布版，而不是把整个工作区压缩。

协作内容按目标、输入输出、分工、修正依据和效果边界概括。聊天原文、会话 ID、原始 API 请求、内部推理和凭据不作为公开材料；没有证据时不补写所谓模型回答。旧归档不自动删除；新版应说明替代关系。

报告若脱敏主机名或路径，数值和技术结论保持原样，分别记录输入哈希与发布哈希。不能再声称发布副本与原件字节相同。用最终内容生成清单，并校验 ZIP 内成员与清单。

```sh
python scripts/audit_release.py <PUBLISH_DIRECTORY>
```

脚本只报告候选文件/行号/规则，不打印命中的敏感值，不修改/删除文件。它检查个人主目录、常见会话 ID、原始聊天角色、私钥和字面凭据。通过后仍要人工阅读摘要，并检视图片、压缩包和陌生二进制；本脚本不是完整匿名化证明。

## 失效条件与来源

业务标识可能与会话 ID 格式相同，须人工判定；扫描不认识的编码、截图、隐写或外部链接不在覆盖范围。发现问题时仅修订新发布目录并重新计算清单，不覆盖原始证据。

经验来自外发交接中过多暴露会话原文的修订。本次用新版发布目录及合成敏感文件夹具检查正常通过和主动检出；未将私密原始数据作为技能示例附带交付。
