# 本项目的合同反填实例

这是已完成项目的事后案例，不是供其他题目照搬的硬编码配置。

| 合同项 | 此实例的填写结果 |
|---|---|
| 目标 | 将裸机拍摄产物交给 Linux 识别，并提供可复制/删除的成品 |
| 生产者/消费者 | 采集固件 → 相册识别；相册识别 → 曲库/播放器 |
| 数据与尺度 | 固定裁切彩照和灰度图，4056×2868；识别消费灰度图 |
| 方向 | 相机输出保留传感器方向；此安装方式约定纸顶朝右，识别端固定 ccw；更换安装方式须重新约定 |
| 命名与提交 | 曲目-页码；Meta 中 complete 为真后才消费对应页 |
| 存储权威 | FAT 为交换区，最终 Outputs 中的 MusicXML 为成品权威；ext4 做运行与缓存 |
| 并发边界 | 两个环境分时使用卡，切换前同步并卸载，不同时写共享分区 |
| 失败行为 | 未完成文件不列入识别；不完整结果不当成功发布；保留原输入用于重试 |
| 验证产物 | 已归档的七页相册状态、逐页进度与完成日志、两首生成 XML；构建报告独立归档 |
| 未覆盖项 | 日志完成不等于逐音准确率；离线事件比较不等于真实扬声器播放或新板验收 |

本例的尺寸、方向和编号值仅用于核对这次真实交接。复用于另一个项目时，应替换目标、格式和完成条件，而不是让新项目迁就这些参数。
