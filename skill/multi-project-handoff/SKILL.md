# 多工作线接口与交接

## 适用

用于多模型、多个已有 Project/会话和硬件/软件/媒体并行协作。先确认与用户目标有关的工作线；不将无关项目纳入总结。本技能不要求新建会话或子代理。

## 工作流

按交付物与接口组织分工，而不是按模型名称分割隐式职责。使用 [合同模板](assets/interface-contract.md) 写清生产者、消费者、数据、方向/单位、完成条件与失败回退；再用 [交接模板](assets/handoff.md) 将各条工作线收束为可审查产物。

每条候选在独立位置验证，交接注明“正式部署 / 已验证未合入 / 试验 / 示意素材”。算法层的单页、批次、端到端和设备实测不可互换。共同保护的真实数据、基线和已发布产物以哈希或语义检查核对，失败候选不能静默替换默认入口。

可复用提示词骨架：

> 输入目标、当前基线、允许修改范围与证据目录。先明确接口和待验证假设，输出最小候选、失败表现、验证结果及未决问题。只总结任务相关的产物，不复述私人对话；缺少证据的效果标为未验证。交接必须说明消费方需要的下一步。

## 何时停止

两条工作线的尺寸、单位、路径权威或模型版本冲突时，不靠猜测强行合并；先指出具体冲突并继续不依赖它的工作。无法证明候选有益时保留原部署。这个模板不能自动证明并行任务无冲突，也不能替代用户对需求的决定。

## 验证与来源

模板抽象自 Claude 识别/加速、采集、独立回归、系统界面和多条宣传工作线的实际交接。本次以已完成工程反填合同并核对尺寸、方向、完成标记与部署范围，实例见 [retrospective-example.md](references/retrospective-example.md)；这是事后案例检查，尚不是另一团队从零迁移的成功证明。
