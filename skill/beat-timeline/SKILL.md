# 节拍与计算原理动画编排

## 适用与输入

用于计算原理解释、工程演示和成片局部调整。输入为 BPM、实际 FPS、有无音乐起拍偏移、已有剪辑锚点、目标时长和真实数据来源。区分计算过程示意、真实录屏与艺术化素材。

## 使用流程

```sh
python scripts/beat_frames.py --bpm <BPM> --fps <FPS> --beats <BEAT_COUNT> --start-frame <ORIGIN>
```

脚本用绝对有理数时间逐个计算拍点，不把四舍五入后的单拍帧数累计；因此适用于非整数 FPS/BPM。用输出锚点填写 `assets/storyboard.csv`，再在 Blender/AE/剪辑软件中实现。它不修改现有媒体、不保证音乐实际是恒速节拍。

画面依次展示真实输入、分块/坐标、模型或几何结果、合并与输出。每个画面写明可追溯输入或“架构示意”；动画时长不等于算法耗时。多核、加速器与存储路径只展示已实现或明确标注为设想的部分。

局部修改若要求后段音乐对齐，保持后续总帧号与原音轨时间戳；需要延长字幕时优先在已授权的邻近镜头内调整，新增总时长则重新与用户目标核对。导出后验证帧数、实际 FPS、时长、关键帧和音轨偏移，而非只看软件时间显示。

## 失效与来源

变速曲、自由速度演奏和非恒定帧率需先建立 tempo map/CFR；本脚本不适用。经验来自 Claude 宣传规划、并行开场/标注工作线及计算原理动画的节奏迭代。离线验证覆盖 90 BPM/30 FPS 和 30000/1001 FPS 的绝对锚点及误差界；没有把素材生成速度当设备运行速度。
